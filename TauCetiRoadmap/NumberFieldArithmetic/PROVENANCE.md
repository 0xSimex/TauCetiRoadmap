# Provenance: number field arithmetic

This file is **not** part of the roadmap. `README.md` is the definitive document, and no
milestone depends on anything recorded here. This file holds the coordination record: which
outside work fixes the design of an object, which licences apply, and who has been contacted.
Its contents change as that outside work changes.

## Mathlib work that fixes a design

Mathlib is consolidating the ramification and inertia theory of Dedekind domains. Mathlib owns
the design of its own API. Where a milestone of the roadmap covers the same ground, the roadmap
uses Mathlib's names and shapes, so that a later Mathlib version replaces the Tau Ceti
declaration by an import and a deletion. No roadmap milestone waits for any of this work.

**Ring-level Hilbert theory.** Mathlib pull request
[#41591](https://github.com/leanprover-community/mathlib4/pull/41591) introduces
`Ideal.IsDecompositionRing` and `Ideal.IsInertiaRing`, and deprecates the field-level
`IsDecompositionField` and `IsInertiaField`. README Layer 1.3 states its milestones so that the
change of class costs nothing. The surrounding series covers:

- splitting in the decomposition field (#35802) and in the inertia ring (#35808);
- decomposition and inertia fields of composita and of subfields (#35991, #36733);
- unramified composita, with the totally-split criterion
  `ramificationIdx_inertiaDeg_sup_eq_one` (#36843);
- the inertia field of `p` in `ℚ(ζ_{p^k m})` (#37031).

**The `ramificationIdx` and `inertiaDeg` definitions.** Mathlib is replacing both by their
localization and residue-field versions (#41234, #41325), keeping the supremum and quotient-rank
forms as `ramificationIdx'` and `inertiaDeg'`. The new definitions also change the argument
order: they take the prime of the extension first and the base **ring** second, where the
definitions at the pin take two ideals. README §Pinned conventions records the resulting rule.

**Neighbouring work.** `Ideal.inertia` API (#40383); the reorganization of the `IsGaloisGroup`
material (#40928, #40942, #41071); the finite-flat `Σ eᵢfᵢ` formula at ring level (#39189);
`Algebra.IsUnramifiedIn` (#41323); `not_dvd_discr_iff_isUnramifiedIn` (#40951); norm congruence
at unramified primes (#41180); coprime discriminants giving linear disjointness (#37023);
composita of abelian extensions (#40905); and "Galois groups are generated by inertia subgroups"
(#40955), the group-theoretic form of the statement that `ℚ` has no unramified extension.

**Where Mathlib has nothing.** There is no conductor–discriminant formula and no ideal-theoretic
conductor. There is no extension of `IsArithFrobAt`, so in particular no Artin symbol. There are
no higher ramification groups. There is no certification of a named fundamental unit. Those are
the core of README Layers 2 to 7, and they duplicate nothing.

**The `Valued` deprecation.** Mathlib is replacing `Valued` by `ValuativeRel`. Mathlib's
`adicCompletion` is `Valued`-based, so README Layer 5.1 states its instances through the
compatibility layer.

## Conventions settled in public discussion

The decomposition group as `MulAction.stabilizer` was settled on the Lean Zulip, in
[new members > "Working on Frobenius elements"](https://leanprover-community.github.io/archive/stream/113489-new-members/topic/Working.20on.20Frobenius.20elements.html)
(M. Karatarakis, with Buzzard, Commelin, Topaz, Lezeau, Wieser, Dillies and Nuccio). That thread
is also the origin of the `ValuationSubring.decompositionSubgroup` stub, which README §What
Mathlib supplies warns against building on.

Chebotarev is a declared goal of PrimeNumberTheoremAnd (Kontorovich and Tao). README §Explicit
scope exclusions states that this roadmap proves no density statement.

## Licence and coordination ledger

**Mathlib.**

- Overlap: decomposition and inertia predicates, and the `e` and `f` names, in README Layers 1
  and 2.
- Licence: Apache-2.0.
- Coordination record: the public Mathlib pull-request discussions cited above.
- Ownership: Mathlib owns the generic ring-level API. This roadmap owns the number-field
  comparisons and the Frobenius layer built on them.

**`CBirkbeck/CertifyingInvariantsNF`** (C. Birkbeck).

- Overlap: certified per-field invariant files, and a database-label interface.
- Licence: none is declared in the repository metadata. No code and no data from it may be
  copied or adapted without explicit permission.
- Coordination record: none. The authors have not been contacted.
- Ownership: this roadmap proves only the intrinsic `d.r.|D|` prefix, and makes no claim on the
  LMFDB ordering or on the canonical-polynomial layer.

**FLT and `kbuzzard/ClassFieldTheory`.**

- Overlap: `Mathlib/RingTheory/Frobenius.lean` is infrastructure adjacent to FLT, and the
  `erd1/LCFT` local class field theory interface normalizes its Artin map at arithmetic
  Frobenius through `IsArithFrobAt`.
- Licence: Apache-2.0.
- Coordination record: public repositories only.
- Ownership: README Layer 2 uses the same `IsArithFrobAt` vocabulary, so the two packagings
  agree by construction.
